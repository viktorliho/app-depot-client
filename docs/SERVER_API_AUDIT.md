# Server API audit (M0)

Audited Server commit `08c749b1124624d33af38a99e03d24ad45ee8564` from the local `app-depot-server` checkout. Contract sources: [OpenAPI](https://github.com/viktorliho/app-depot-server/blob/main/docs/openapi.yaml), [API semantics](https://github.com/viktorliho/app-depot-server/blob/main/docs/api.md), [architecture](https://github.com/viktorliho/app-depot-server/blob/main/docs/architecture.md), [Tree Identity v1](https://github.com/viktorliho/app-depot-server/blob/main/docs/tree-identity.md). Implementation evidence: `crates/server/src/{auth,catalog,download,declarations,artwork,channels}.rs`, `crates/infrastructure/src/{catalog,declarations,channels,artwork}.rs`, and `crates/server/tests/upload_http.rs`. “Verified” here means inspected in source or existing tests, not an M0 live compatibility run.

## Read contract and implementation findings

| Concern | Documented contract | Implementation evidence / qualification |
| --- | --- | --- |
| API and capabilities | `/api/v1`; `GET /capabilities` reports `apiVersion`, identity formats, `downloadRanges`, limits and features. Pre-1.0 compatibility is not promised. | `download.rs::capabilities` currently emits `apiVersion: 1.0.0`, `adfile:sha256`, `adtree:v1:sha256`, `downloadRanges: true`, max page 1000 and optional `serverImport`. Version is the API value, not a promise that the product is 1.0. A client must inspect fields rather than assume future Servers have the same set. |
| Authentication | Optional personal Bearer token; anonymous reads require a global setting and Public Published content. Owners and Admin can read their Private/Draft content. Hidden resources return 404; protected actions without authentication return 401. | `auth.rs` parses `Authorization: Bearer`; catalog, download, declarations and artwork handlers call reader authorization. Catalog SQL and download SQL check owner/Admin or Public Published. No client login or token issuance is required for MVP. |
| App and Release discovery | `GET /apps`, `/apps/{id}`, `/apps/{id}/releases`, `/releases/{id}`. App UUID and Release UUID are distinct; versions may be absent. | `catalog.rs` handlers and storage list by ID. Visible App listing includes owned resources plus eligible Public Published; Release listing includes Draft for manager, Published for other authorized readers. |
| Publication/visibility | Draft and Published are distinct from Private/Public. Upload registration does not publish. Published Release composition is frozen; a Published App may be Private. | `catalog.rs` and storage access checks enforce the distinction. The client must display state and access failure, not assume all Public Apps have downloadable Drafts. |
| Channels/selection | `GET /apps/{id}/channels` and `GET /apps/{id}/channels/{name}`; channels are optional mutable pointers to Published Releases, with no built-in stable/latest channel. | `channels.rs` stores names and release IDs. M1 lists releases explicitly. Any “latest” ordering by version/date would be client policy and cannot silently stand in for a Server channel. |
| Artifact associations | `GET /releases/{id}/artifacts` returns association IDs with Release and Artifact IDs; `GET /associations/{id}` and `GET /artifacts/{id}` give separate context/content. Multiple associations per Release. | `catalog.rs::list_associations` and `download.rs::artifact` confirm. Artifact bytes may be shared while association declarations differ. No primary Artifact field is defined. |
| Declarations | Independent App, Release and association documents, revision IDs and histories; any JSON `data` value including null. Combined `GET /releases/{id}/declaration-snapshot` is consistent and has a strong ETag. | `declarations.rs` stores JSON values/revisions and assembles snapshot. Typed projections must retain the original data and unknown properties. An ETag is a validator, not an identity or authorization. |
| Entry points | Optional association `data.appDepot.entryPoints`: stable association-local `id`, optional label/platforms and `ArtifactFile` or `TreeFile` target. No default, executable-bit requirement or execution behavior. Read-only validation endpoint exists. | `server/src/declarations.rs::validate_entry_points` checks shape and target in inventory and reports `Absent`, `Valid`, `Issues`, `Unsupported`; it does not create revision or grant execution. Integration test covers valid, invalid, missing, wrong kind, and unknown extension preservation. |
| Platform/runtime/install/dependencies | Release `appDepot.platforms` is a free-form string array; Release `appDepot.runtime` has optional free-form `name`/`version`. Entry-point platforms narrow applicability. Installation and dependency fields are not standardized. | Portal validation and storage permit optional fields; no Server execution machinery. No normalized OS/architecture vocabulary, portable-app marker, working directory, arguments, installation operation, dependency detector or preparation operation is defined. These are **contract gaps**, not hidden behavior to infer. |
| Artwork | App-owned `GET /apps/{id}/artwork` enumerates roles; `GET /apps/{id}/artwork/{role}/content` returns original image bytes; absent binding is 404. | `artwork.rs` implements current binding lookup and content, independent of Artifact associations; integration test exercises private/public access, replacement and restore. Validate image bytes and resource limits locally before display/cache. |
| Single-file download | `GET /artifacts/{id}/content`; file ID embeds its SHA-256. | `download.rs` checks an accessible association and verifies CAS bytes before serving. Client still verifies full local bytes. |
| Tree download | `GET /artifacts/{id}/inventory` pages original paths, directory entries, `fileId`, size, SHA-256, executable; `GET /artifacts/{id}/files/{fileId}` returns each file. | `download.rs::inventory/tree_file` enforce authorization. Inventory has ETag, stable pagination for immutable tree; `parent`/`q` filters exist but M1 uses unfiltered inventory. Server file IDs are opaque and are not filesystem paths. |
| Pagination | `pageSize` default 100, max 1000 or advertised lower; opaque `cursor`; `nextCursor: null`; invalid cursor is `400 invalid_cursor`. Pages are internally consistent, but catalog traversal is not a global snapshot. | `catalog.rs::page` and `download.rs::inventory` implement cursor binding to scope/filter/page size. Restart traversal after invalid cursor. Parse uint64 exactly. |
| HTTP ranges | Single byte `Range`, strong ETag and `If-Range`; matching validator gives 206, mismatch gives full 200, unsatisfiable range gives 416 plus `Content-Range: bytes */total`. Multiple ranges may yield 200. | `download.rs::range/serve_file` implements open-ended and suffix ranges, full-200 fallback and 416. Tree files use a file-digest ETag; inventory has a distinct Artifact ETag. Resume must validate response status, range and expected identity before append. |
| Integrity and errors | File SHA-256 and canonical Tree Identity v1; RFC 9457 Problem Details with code; 401/403/404, 400 invalid cursor, 416 range failure, 429 rate limit, 503 retryable failure, etc. | `download.rs` and `auth.rs` return these shapes. Retry only transient transport/429/503 and bounded 5xx with backoff; never retry a digest mismatch as success. Reauthorization can fail after an offline copy exists; local completed files remain local. |

## MVP operation map

| MVP operation | Existing API |
| --- | --- |
| Connect and negotiate | `GET /capabilities` |
| Public or Bearer catalog | `GET /apps`, `/apps/{id}/releases`, `/releases/{id}` |
| Discover all Artifact choices | `GET /releases/{id}/artifacts`, `/artifacts/{id}` |
| Read declarations | `GET /releases/{id}/declaration-snapshot`; optionally per-scope current documents and entry-point assessment |
| Read artwork | `GET /apps/{id}/artwork`, `/apps/{id}/artwork/{role}/content` |
| Download file or tree | `GET /artifacts/{id}/content` or `/inventory` plus `/files/{fileId}` |
| Resume/verify | `Range` + `If-Range`; local SHA-256 and Tree Identity v1 |
| Offline library/progress | Client-local state; no Server endpoint needed |
| Install/launch | Outside M1; shared declaration semantics are incomplete |

No Server API change is required for the download-focused MVP. The lifecycle gaps in [DECLARATIVE_LIFECYCLE.md](DECLARATIVE_LIFECYCLE.md) need a shared contract decision before an implementation claims installation or launch support.
